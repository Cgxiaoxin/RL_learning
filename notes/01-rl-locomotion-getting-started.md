# 机器人运控强化学习：入门路线

记录日期：2026-11-20

## MuJoCo 和 mjlab 的关系

MuJoCo 是物理仿真引擎：根据模型、控制输入和物理规律计算机器人状态如何变化。经典 Python 接口中的 `mujoco.mj_step` 推进一步物理仿真。

MuJoCo Warp 是针对 GPU 并行仿真的实现，适合同时推进大量环境。mjlab 建立在 MuJoCo Warp 等组件之上，提供机器人模型、任务、观测、动作、奖励、重置和训练接口；它通过 RSL-RL 等算法库训练策略。两者不是同一个东西，可以将 MuJoCo 理解为物理引擎，mjlab 理解为组织训练的框架。

训练时的基本闭环：速度指令与机器人状态 → 策略生成动作 → 控制器执行 → 物理仿真更新状态 → 根据奖励和采样数据更新策略。具体动作是否为关节位置目标、PD 参数和控制频率，要查实际任务配置。

## 硬件评估

本机 NVIDIA GeForce RTX 4060，显存约 8 GB；所提供的 `nvidia-smi` 显示已用约 1 GB，驱动版本 580.178.04。Linux + NVIDIA GPU 符合 mjlab 官方列出的训练平台方向，但是否能运行某个任务、具体并行环境数及速度必须实际测试；8 GB 并非保证可运行任意配置。

本机适合学习、少量环境调试、可视化和回放。正式训练与多组对比可先使用服务器单张 5090；A800 也可以使用。先以相同版本、任务、环境数量和配置实测速度与显存，再决定选卡。`nvidia-smi` 的 CUDA Version 表示驱动支持的最高 CUDA 版本，并不证明对应 CUDA 工具包已安装，也不能单独证明 PyTorch 或 Warp 可用。

## 建议的任务顺序

1. **倒立摆 Cartpole**：理解状态、动作、奖励、终止和训练/评估；它是入门控制任务，不是腿足运动。
2. **四足平地速度跟踪**：先理解站稳、跟踪前进速度，再尝试横向和转向指令；关注关节目标、PD 和控制周期。
3. **人形平地速度跟踪**：观察平衡与步态，理解奖励项和终止条件。
4. **鲁棒性**：对照基线，逐项加入摩擦、质量、推扰或地形变化，记录跟踪误差、摔倒率和视频。
5. **Sim2sim**：将策略迁移到另一仿真器，核对关节顺序、坐标系、控制频率、PD、观测和动作缩放；通过仿真不代表真机安全。

## 第一次实验建议

1. 选定并记录 mjlab 版本、驱动和依赖，按官方安装指南建立独立 Python 环境。
2. 从官方 demo 或 Cartpole 教程验证安装；通过 zero/random 策略检查动作和环境行为。
3. 在本机从少量并行环境开始做短时间冒烟测试，检查显存、吞吐、是否正常保存和回放；如果显存不足，就减少并行数或转服务器。
4. 在服务器单卡运行平地速度跟踪基线，记录任务名、配置、环境数、迭代、实际耗时、显存和指标；再修改一个变量做对照。
5. 对比时注意：改变并行环境数会改变采样量和训练动态，不能直接把不同配置的迭代数视为等价训练量。

多卡训练中，每张卡各自运行配置的 `num-envs`，再同步策略梯度，并不会自动将环境数量均分。显存也不会自动合并给单个环境使用。
